# Security Policy

## Supported Versions

This project is a reusable template rather than a published application package.

Security fixes are provided for the latest version available on the default branch. Older forks and customized copies are maintained by their respective owners.

## Reporting a Vulnerability

Please do not report security vulnerabilities through a public issue, discussion, pull request, or comment.

Use GitHub's private vulnerability reporting feature:

1. Open the repository's **Security** tab.
2. Open **Advisories**.
3. Select **Report a vulnerability**.
4. Include clear reproduction steps, the affected files or behaviour, the potential impact, and any suggested mitigation.

If private vulnerability reporting is unavailable, contact the maintainer through a private contact method listed on their GitHub profile. Do not disclose vulnerability details publicly.

## What to Include

A useful report should include:

- A concise description of the vulnerability
- Steps to reproduce it
- The affected browser, operating system, dependency, or configuration
- The expected and actual behaviour
- The potential security impact
- Proof-of-concept material that does not expose real users or sensitive data
- A suggested fix, when available

## Response Process

The maintainer will review the report, request clarification when necessary, and determine whether the issue affects the reusable template.

Valid reports will be handled privately until a fix or mitigation is available. A security advisory may be published after the issue is resolved.

## Scope

Examples of issues that may be in scope include:

- Unsafe URL handling
- Cross-site scripting or script injection
- Vulnerable production dependencies
- Exposure of secrets or personal data caused by the template
- Security defects in sharing, QR-code, or link behaviour
- Configuration validation that permits unsafe values

The following are generally outside the template's scope:

- Vulnerabilities introduced only by a user's custom code
- Problems caused by exposing secrets in a public configuration file
- Deployment-platform or hosting-account issues
- Social engineering
- Denial-of-service testing against third-party services
- Automated reports without a reproducible security impact

## Responsible Disclosure

Allow reasonable time for investigation and remediation before publishing vulnerability details.

Do not access, modify, retain, or disclose data that does not belong to you.
